# 既有状态迁移

当前版本使用一个 Node.js 24 / TanStack Start 服务运行网页、Telegram 账号管理、扫描下载、SQLite 队列和 Emby 刷新。新安装请直接按 [README](../README.md) 配置，无需执行迁移。

## 迁移前

1. 停止旧下载器、旧管理后台以及所有使用同一状态卷的进程。旧服务和新服务不能并行使用同一 SQLite、会话或配置目录。
2. 完整备份 SQLite 状态目录、Telegram 会话、业务配置、环境文件、临时下载文件和最终媒体。不要只复制正在写入的 SQLite 主文件。
3. 记录原目录挂载、卷名与文件权限。迁移期间保留旧镜像和备份，避免原地删除或清卷。

## Docker 迁移

1. 复制 `management.env.example` 为私密的 `management.env`，设置原 `TG_API_ID` / `TG_API_HASH`、正确的 `WEB_ORIGIN` 和媒体路径。
2. 将 `TELEGRAM_STATE_VOLUME` 指向旧状态卷，`MEDIA_PATH` / `TEMP_PATH` 指向原有媒体与临时目录。确认卷内 SQLite 和会话文件名与 `compose.web.yaml` 中的路径一致；若不同，先调整挂载和环境路径。
3. 将完整的原业务配置放入配置卷的 `/configuration/config.json`，保留作品规则和 `account_id`；配置现在可能包含 Emby Key，应设为 `0600`。
4. 确认 UID/GID `1000:1000` 对状态、配置、会话、媒体及临时目录具有所需权限。媒体目录及 `.incoming` 必须在同一文件系统。
5. 按根 README 构建并启动单服务，查看启动日志与账号、频道、扫描和下载页面。如果缺少账号授权，在网页重新登录原账号。

## 兼容行为

- SQLite 沿用原表、任务复合主键、账号记录和频道游标，并补充缺失列。媒体文档 ID 在 TypeScript 接口中使用十进制字符串，避免 64 位整数精度损失。
- 旧 Telethon SQLite 会话会被只读提取 DC 与授权密钥，转换为相邻的 StringSession 文件（默认 `telegram.session.string`，权限 `0600`），原会话保留。会话已失效时仍需重新登录。
- 没有账号记录而存在旧会话时，会登记为 `legacy`；未指定账号的旧频道会使用兼容账号。已有多账号配置应保持原有 `account_id` 绑定。
- 未完成任务会按恢复逻辑继续处理；文件发布仍校验大小且禁止覆盖冲突目标。配置变更不会自动删除已完成媒体。
- Emby 地址和 Key 可在设置页保存。保存值优先于环境默认值，Key 不通过状态接口回显。刷新失败单独重试，不重新下载视频。

## 回滚与验证

迁移遇到问题时先停止新服务，保留故障现场，再成套恢复迁移前的状态、配置和会话备份后启动旧版本。不要假定升级后的 SQLite 可直接交给旧代码使用，也不要执行 `docker compose down -v`。

开发验证仅使用 `127.0.0.1:13000/18765`、`127.0.0.1:13001/18766`、临时目录、独立测试令牌与模拟 Telegram 传输。自动测试不连接线上服务，也不复用真实会话、凭据或媒体卷；模拟结果不能证明真实 Telegram 授权、频道权限或 Emby 索引已通过。
